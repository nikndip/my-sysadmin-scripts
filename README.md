# Журнал ресурсов Ubuntu

Домашнее задание №1 по системному администрированию. Выбран вариант Б — мониторинг ресурсов.

`script.sh` собирает показатели учебной Linux-машины и сохраняет их в `monitor.log`. Каждая запись содержит время измерения, сведения о памяти, файловых системах и нагрузке. Предыдущие записи сохраняются при повторном запуске.

## Начало работы

Склонируйте репозиторий и запустите скрипт из его каталога:

```bash
git clone https://github.com/nikndip/my-sysadmin-scripts.git
cd my-sysadmin-scripts
./script.sh
```

Если репозиторий уже находится на машине, достаточно перейти в его каталог и выполнить `./script.sh`.

Для работы нужны Bash и команды `date`, `free`, `df`, `uptime`, `sleep`. Скрипт проверен на Ubuntu 22.04.5 LTS с архитектурой aarch64.

После запуска терминал показывает сообщение с интервалом и именем файла. Сами показатели записываются в лог. Для остановки нажмите **Ctrl+C**.

## Как устроено наблюдение

Перед началом скрипт проверяет интервал, наличие необходимых команд и возможность открытия лога для записи.

Первый блок записывается сразу. Далее после каждого блока выполняется пауза, заданная константой:

```bash
INTERVAL=5
```

Интервал меняется редактированием `script.sh`; вводить его при запуске не требуется. Промежуток между временными метками может быть немного больше 5 секунд из-за времени выполнения команд и планирования процессов.

## Содержимое журнала

Каждый блок начинается строкой вида:

```text
--- 2026-10-11 21:46:09 ---
```

Время берётся из системных часов Ubuntu-машины. После метки идут три подписанных раздела:

- **Память (`free -h`)** — общий объём RAM, использование памяти, доступная память и swap.
- **Файловые системы (`df -h`)** — размеры, занятое и доступное место, процент заполнения и точки монтирования.
- **Время работы и нагрузка (`uptime`)** — время после запуска системы, число вошедших пользователей и средняя нагрузка за 1, 5 и 15 минут.

Флаг `-h` делает размеры памяти и файловых систем удобными для чтения.

`monitor.log` создаётся в **текущем каталоге запуска**. Запуск из папки репозитория сохраняет журнал в этой папке. Перенаправление `>>` дописывает данные в конец файла.

Просмотр последних записей:

```bash
tail -n 60 monitor.log
```

Три полных блока реального запуска сохранены в [sample_output.txt](sample_output.txt).

## Завершение и ошибки

При Ctrl+C или сигнале SIGTERM скрипт выводит сообщение об остановке и завершается с кодом `0`.

Проверки перед запуском завершают скрипт с кодом `1`, если:

- интервал не является целым положительным числом;
- отсутствует одна из необходимых команд;
- невозможно открыть `monitor.log` для записи.

Сообщения об ошибках направляются в stderr. Режим `set -euo pipefail` прекращает выполнение при других необработанных ошибках, обращении к неопределённым переменным и ошибках в конвейерах.

## Проведённые проверки

Работа проверена на учебной машине:

- `bash -n script.sh` — синтаксических ошибок нет.
- Обычный запуск — получены повторяющиеся блоки со всеми тремя разделами.
- Повторный запуск — новые записи добавлены к существующему журналу.
- Остановка по Ctrl+C — управление возвращается в терминал, код завершения `0`.
- Ошибка записи — во временной папке создан каталог с именем `monitor.log`; скрипт сообщил об ошибке и завершился с кодом `1`.
